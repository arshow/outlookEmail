# 手动获取邮件进度

单邮箱和聚合收件箱点击获取按钮后，统一在右上角浮动任务面板显示批次、耗时和已读取邮件数；
邮件列表区域不再重复显示进度卡片或手动获取状态条。
单邮箱按文件夹统计，聚合收件箱按邮箱统计；进度条表示当前批次已结束的请求比例，
成功、失败、部分失败分别计数，超时是其中的补充统计。

右上角“收信任务”图标可展开浮动任务面板。每次手动获取生成独立记录，支持单邮箱和聚合收件箱；
面板不会因任务结束、切换邮箱、点击页面其他位置而自动关闭，只能通过图标或关闭按钮手动收起。
保留最近 20 条已结束记录，运行中的任务不会被清除，失败记录可再次打开错误详情。
已结束任务可点击“删除记录”，或点击“清空已完成记录”批量删除所有已结束记录（包括部分失败和失败）。
删除同时移除当前浏览器中的持久化记录，刷新后不会恢复；运行中的任务不提供删除按钮，也不会被批量清空。
切换邮箱或分组后，原任务继续获取并更新浮层，按发起时的邮箱、分组和文件夹完成后续分页，
不会把原任务的结果写入当前邮箱视图。

任务记录和面板展开状态保存在同一浏览器、同一站点的 localStorage 中，刷新或重新打开页面后恢复。
只保存任务范围、批次、后台请求标识、统计、邮件标识和错误信息，不保存邮件正文或邮箱凭据；
完成后不再保存用于分页去重的邮件标识。浏览器禁止存储或空间不足时，面板会提示无法保证恢复。

页面初始化会自动查询未完成的原后台请求，不会重新提交正在执行的批次。
当前批结束后，按原邮箱、分组、文件夹和页大小继续剩余分页；每批使用稳定标识，重复恢复不会重复创建同一批任务。
若后台服务已重启或结果超过保留期限，会保留任务记录并标记失效，提示重新获取，不会无限显示进行中。

邮件列表 GET 请求可附加 `progress_id`（32 位小写十六进制随机标识，每批使用新值）。
服务端仍按原接口返回邮件结果，并额外返回 `fetch_progress`。

网页的手动获取会同时使用 `async=1`：接口立即返回 HTTP 202 和 `pending=true`，
收信在后台执行。前端通过进度接口附加 `result=1`，用短请求轮询进度和最终 `result`，
避免等待 Graph/IMAP 的长 HTTP 连接被反向代理提前以 504 中断。原同步接口保持兼容。
后台任务完成结果保留 15 分钟，最多保留 32 个任务、同时执行 8 个任务；服务重启后清空。

`GET /api/emails/fetch-progress/<progress_id>` 需要正常 Web 登录，返回：

```json
{"success":true,"progress":{"state":"running","total":2,"completed":1,"successful":1,"failed":0,"partial":0,"timed_out":0,"fetched":10,"active":["junkemail"],"elapsed_seconds":5.2}}
```

请求尚未开始、标识不存在或已过期时，`progress` 为 `null`。状态仅保存在当前单 worker 内存中，
30 分钟无更新后过期，服务重启后清空；最多保留 128 个请求。该接口不返回邮件正文或凭据。
